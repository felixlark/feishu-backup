# 为什么 `feishu-docx` 不等于完整备份

## 标题

为什么单纯导出飞书文档，不等于你真的完成了知识库备份

## 导语

很多人已经在用 `feishu-docx` 导出飞书文档，它很好用。但“能导出文档”和“能长期做知识库备份”是两个不同层级的问题。

## 对比结构

### 手工导出

- 一篇篇点，容易漏
- 没有增量同步
- 没有恢复点

### `feishu-docx`

- 很好的导出引擎
- 适合把单篇或一批文档导出成 Markdown
- 但不负责备份状态、调度、恢复、归档

### `feishu-backup`

- 复用 `feishu-docx` 作为导出基础
- 额外处理 space discovery、增量 sync、断点续传、本地归档、定时运行
- 面向的是“持续备份”这个问题

## 结尾

它不是替代 `feishu-docx`，而是把它变成一个真正能长期运行的备份工作流。
